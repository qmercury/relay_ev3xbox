# 얼라이언스 Relay 운영

EV3 Xbox Relay는 학생 코드와 별개의 프로그램입니다.

한 노트북에서 Xbox 여러 개를 각각 다른 EV3에 1:1로 연결할 수 있습니다.

```text
Xbox 1 ─┐
Xbox 2 ─┼─ Bluetooth → Relay 노트북
Xbox 3 ─┘                    │
                              │ 로컬 Wi-Fi
                   ┌──────────┼──────────┐
                   ↓          ↓          ↓
                 EV3 1      EV3 2      EV3 3
```

## 대회장 인터넷 없이 운영하는 공용 무선망 (현재 확정 요구사항)

대회장 제공 Wi-Fi와 인터넷에는 의존하지 않습니다. **코치가 공용 공유기/AP 1대를 보조배터리로 전원 공급하여 켜 두고**, 서로 다른 팀의 Relay 노트북과 EV3가 같은 로컬 Wi-Fi에 연결됩니다. 별도 공유기를 팀별로 한 대씩 두지 않는 구성이 우선안입니다.

### 접속 규모와 전원

- **총 출전 EV3 18대**: 경기하지 않는 EV3는 전원을 꺼 놓고 최대 9대 동시 접속으로 운영
- **동시 접속 Relay 노트북 최대 3대** (팀 전체 수 5~9팀과 구분)
- **경기 중 Wi-Fi 클라이언트 최대 12대** = EV3 9대 + 노트북 3대 (대기 로봇은 전원 OFF). 모든 EV3가 켜져 있다면 21대가 되므로 이를 피하도록 관리
- Xbox 컨트롤러는 각 노트북에 Bluetooth로 연결하므로 AP의 Wi-Fi 접속 대수에 포함하지 않음
- Relay 노트북 1대당 Xbox/EV3 최대 3세트를 운용하며 동시 제어 로봇은 최대 9대; 나머지 EV3는 전원을 꺼 두어 Wi-Fi 클라이언트 수를 제한
- 공유기는 **최대 12대 접속**에서 지연과 안정성을 우선 검증. TL-WR802N은 USB 전원 후보이나 공식적인 12대 실시간 제어 안정성은 검증 전
- 공유기 전원은 **코치 보조배터리 → 공유기 USB 전원**. 각 팀 노트북은 자신의 배터리를 사용하며 공유기에 전원을 공급하지 않음

```text
코치 보조배터리 ── USB 전원 ── 공용 로컬 Wi-Fi 공유기/AP
                                       │  (인터넷 WAN 연결 없음)
                       ┌───────────────┼──────────────────┐
                       ↓               ↓                  ↓
                  Relay 노트북 1    Relay 노트북 2    Relay 노트북 3
                  Xbox 최대 3개    Xbox 최대 3개     Xbox 최대 3개
                       │               │                  │
                       └── Wi-Fi로 공용 AP를 통해 EV3 18대 중
                                    팀에 배정된 로봇을 제어
```

### 공유기/AP 구매 조건

- 2.4GHz Wi-Fi와 EV3의 USB Wi-Fi 동글 호환성, WPA2-PSK, DHCP 서버 기능
- WAN/인터넷 케이블 없이 SSID 유지, 로컬 UDP 브로드캐스트(검색, 포트 5005) 및 유니캐스트 제어 허용
- 클라이언트 격리(AP isolation) 해제 가능, 충분한 DHCP 주소 풀(노트북 3대+EV3 18대 이상)
- 실제 **12대 동시 접속**과 여러 노트북의 컨트롤 패킷 처리에 대한 안정성 확인
- USB 전원 전압/전류, 보조배터리 출력 및 예상 사용시간 확인
- 대회 규정에서 사설 AP/무선 송신 허용 여부 확인
- 앞서 소규모 실험 후보로 제시한 TP-Link TL-WR802N(5V/1A)은 **21대 접속·실시간 제어에 대한 현장 검증이 없으므로 최종 추천 모델로 확정하지 않음**

### 다중 Relay 안전 설계 — 구현/검증 필요

- EV3 18대의 `robot_id`는 모두 고유해야 함. 여러 팀이 동일한 EV3-01을 쓰지 않도록 대회 전체 ID 관리
- 현재 EV3 서비스는 여러 노트북의 heartbeat/제어 요청에 대한 **소유권 인증·잠금이 없음**. 다른 팀 노트북이 우연히 같은 로봇을 지정하면 세션 간섭이나 정지가 발생할 수 있음. 로봇별 Relay 소유권 및 승인된 제어 주체 검증을 개발해야 함
- 한 노트북 장애/한 EV3 오류가 다른 로봇 조종에 영향을 주지 않도록 독립 연결 및 failsafe 검증
- Wi-Fi 연결/초기 자동 검색/중복 Robot ID 확인/실제 DHCP 갱신/EV3 최대 9대 접속/최대 3개 노트북 동시 운용을 순차적으로 시험

### 기존 실험 결과

Mac mini의 macOS 인터넷 공유 기능으로 인터넷 없는 자체 AP 생성을 시도했지만 SSID가 검색되지 않았고 공유 관련 인터페이스/프로세스도 확인되지 않았습니다. 이는 **실험한 Mac mini 환경에서의 실패**이며 Windows 자체 AP의 가능 여부를 증명하거나 부정하지 않습니다. 현재 우선안은 코치가 관리하는 공용 배터리 구동 AP입니다.

## EV3는 IP가 아니라 Robot ID로 찾습니다

EV3의 Wi-Fi IP는 DHCP로 자동 배정되어 바뀔 수 있습니다.

따라서 Relay 프로필에는 EV3 IP를 저장하지 않습니다. 각 EV3에 한 번만 고유한 Robot ID를 지정하고, Relay가 현재 IP를 자동으로 찾습니다.

예:

```text
최서안
Robot ID: EV3-01
Xbox 이름: 최서안 Xbox
```

Relay 내부에서는 실행할 때마다 다음처럼 현재 주소를 자동으로 연결합니다.

```text
EV3-01 → 192.168.137.23
EV3-02 → 192.168.137.31
EV3-03 → 192.168.137.18
```

다음 연결에서 DHCP 주소가 바뀌어도 Robot ID가 같으면 다시 찾아냅니다.

## Robot ID 설정

각 EV3에는 처음 한 번만 고유 ID를 저장합니다.

권장 형식:

```text
EV3-01
EV3-02
EV3-03
```

영문, 숫자, 마침표, 밑줄, 하이픈을 사용할 수 있고 최대 32자입니다.

`.vscode/ev3-target.json`에 다음처럼 넣으면 Xbox 서비스를 설치할 때 함께 저장됩니다.

```json
{
  "host": "192.168.77.2",
  "user": "robot",
  "robot_id": "EV3-01"
}
```

이미 서비스가 설치된 EV3는 다음 명령으로 ID만 변경할 수 있습니다.

```bash
python3 tools/ev3_service.py set-id EV3-01
```

Windows에서는 Python 명령이 `python`인 환경도 있습니다.

```bash
python tools/ev3_service.py set-id EV3-01
```

설정 후 Xbox 서비스가 재시작되고 새 Robot ID로 검색됩니다.

## 자동 검색 방식

Relay 프로그램은 로컬 네트워크에 EV3 검색 요청을 주기적으로 보냅니다.

```text
Relay 노트북
   │
   ├─ "사용 가능한 EV3 있나요?"
   │
   ├──→ EV3 EV3-01
   ├──→ EV3 EV3-02
   └──→ EV3 EV3-03
```

각 EV3의 `xbox_service.py`가 자신의 Robot ID와 함께 응답합니다.

```text
EV3-01 → 현재 IP 192.168.137.23
EV3-02 → 현재 IP 192.168.137.31
EV3-03 → 현재 IP 192.168.137.18
```

사용자는 IP를 직접 입력하지 않습니다.

같은 Robot ID를 가진 EV3가 두 대 이상 발견되면 안전을 위해 그 Robot ID의 중계를 시작하지 않습니다. 먼저 EV3 ID를 서로 다르게 수정해야 합니다.

## 선수 / EV3 / Xbox 이름

각 Relay 카드에서 사용자가 관리하는 값은 세 가지입니다.

```text
선수 이름
EV3 ID
Xbox 이름
```

예:

```text
최서안 / EV3-01
Xbox: 최서안 Xbox
EV3: EV3-01 · 192.168.137.23
```

IP는 상태 확인을 위해 화면에 표시될 수 있지만 직접 입력하거나 저장하는 값은 아닙니다.

프로필은 Git 저장소에 저장하지 않고 Relay 컴퓨터의 사용자 설정 폴더에 저장합니다.

- Windows: `%APPDATA%/EV3XboxRelay/profile.json`
- macOS: `~/Library/Application Support/EV3XboxRelay/profile.json`
- Linux: `~/.config/EV3XboxRelay/profile.json`

## 대회 중 상태 확인

화면 상단에는 전체 상태가 표시됩니다.

```text
준비 3/3 · 중계 3/3
```

각 카드에는 Xbox와 EV3 상태가 따로 표시됩니다.

```text
최서안 / EV3-01                    중계 중

● Xbox: 최서안 Xbox
● EV3: EV3-01 · 192.168.137.23

EV3-01 중계 중입니다.
```

Xbox 또는 EV3가 끊기면 해당 카드만 중지되고 다른 두 로봇의 중계는 계속됩니다.

연결이 복구되어도 중계가 자동으로 다시 시작되지는 않습니다. 카드가 다시 준비 상태가 된 뒤 `중계 시작`을 눌러 재개합니다. 스틱이 기울어진 상태에서 갑자기 로봇이 움직이는 것을 막기 위한 안전 동작입니다.

## 전체 중계 시작 / 긴급 정지

`전체 중계 시작`은 Xbox와 EV3가 모두 준비된 카드만 시작합니다.

`전체 긴급 정지`는 모든 활성 중계를 동시에 정지합니다.

개별 장비 고장이나 연결 끊김은 다른 로봇의 중계를 정지시키지 않습니다.

## 사용 규모

같은 Relay 프로그램을 다음처럼 사용할 수 있습니다.

```text
중계 1개       개인 수업
중계 3개       대회 얼라이언스
중계 여러 개   교사 관리
```

카드가 화면보다 많아지면 마우스 휠로 카드 영역을 스크롤합니다.

## 현재 검증 상태

2026-10-11까지 센터 Wi-Fi 환경에서 다음 테스트는 실기 검증했습니다.

- EV3 한 대(`EV3-01`) Robot ID 자동 검색 및 SSH 접근
- EV3 재부팅 후 Wi-Fi 자동 연결 / Xbox 서비스 systemd `enabled`, `active`
- Relay GUI 종료와 재실행 후 `준비됨` 복구, **중계 자동 시작 방지**
- 수동 `준비됨 → 중계 중 → 준비됨` 전환
- 임시 설정 파일에 잘못된 IP를 넣어도 Robot ID 기준 실제 주소 재발견
- EV3 ConnMan `IPv4.Configuration = Method=dhcp` 확인
